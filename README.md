# Profik.kz — витрина производителя PFS

Клиентский сайт (storefront) для PFS (Professional Fighting Sport) — производителя
оборудования для единоборств в Казахстане. Реализует техническое задание из
`PFS_Digital_Platform_Blueprint` (Тома 0–9).

Это **отдельная система** от PFS APP (внутренний учёт заказов и прайса — репозиторий
`Stibik-PO-PFS`). По архитектуре Тома 0: **PFS APP владеет данными, сайт их только
отображает.** В боевой версии каталог приходит из PFS APP по REST API; здесь для
автономной работы используется локальная копия-сид в `lib/`.

## Стек (Том 0, п. 0.4)

- **Next.js 14 (App Router) + TypeScript** — SSR/SSG обязателен для SEO
- **Tailwind CSS** — дизайн-система (тёмная, красный акцент, mobile-first)

## Запуск

```bash
npm install
npm run dev      # http://localhost:3000
# или
npm run build && npm start
```

## Админка

Вход: **`/admin`** (или «Вход для сотрудников» в подвале). Пароль по умолчанию —
`admin`, задаётся переменной `ADMIN_PASSWORD`; подпись сессии — `SESSION_SECRET`.

Разделы (Том 7): панель управления (KPI, график, топы, алерты), товары
(цены/остатки грузятся фидом, редактируются витринные поля и канал), конструктор
главной (порядок/скрытие блоков + предпросмотр + черновик/публикация — реально
управляет живой главной), категории (баннер, тексты, порядок, SEO), модерация
отзывов, заявки (сюда падают формы с сайта), SEO с GEO-фактами, роли, журнал.

**Excel** (раздел «Товары»): кнопка «Выгрузить в Excel» отдаёт прайс `.xlsx`;
«Загрузить из Excel» обновляет цены/остатки/сроки/названия по артикулу — эмуляция
фида из PFS APP, пока API не подключён.

**Фото**: загрузка маркетинговых фото товара и баннера категории прямо в админке.
Хранятся под `DATA_DIR/uploads`, отдаются через `/media/…`. На проде — persistent
disk на Render (указать `DATA_DIR` на него) или S3/CDN (Том 0, п. 0.4).

**Статистика**: визиты/конверсия — демо-цифры, пока не задан `GA4_ID` (тогда в
дашборде висит пометка). Заявки и переходы на Kaspi считаются из базы сайта уже сейчас.

Данные админки для прототипа хранятся в JSON-файле (`DATA_DIR`, по умолчанию `.data/`).
В бою — PostgreSQL базы сайта; номенклатура/цены остаются в PFS APP (Том 0, п. 0.1).

### Переменные окружения

| Переменная | Назначение |
|---|---|
| `ADMIN_PASSWORD` | пароль входа в `/admin` (по умолчанию `admin`) |
| `SESSION_SECRET` | подпись сессии админки |
| `SITE_INDEXABLE` | `true` открывает индексацию (на тех-домене держим `false`, Том 0) |
| `DATA_DIR` | папка хранилища админки и загруженных фото |
| `GA4_ID` | идентификатор Google Analytics 4 для реальной статистики |
| `GOOGLE_SITE_VERIFICATION`, `YANDEX_VERIFICATION` | коды подтверждения вебмастеров |

## Данные (сид → API PFS APP)

- `lib/company.ts` — единый источник фактов о компании (Том 5, п. 5.5). Значения
  с пометкой `[РЕАЛ]` уточняются заказчиком (год основания, телефоны, адрес).
- `lib/categories.ts` — 8 категорий, подкатегории, фильтры (Том 2, п. 2.4).
- `lib/products.ts` — демо-каталог (локальная копия). В проде заменяется на данные
  из PFS APP по контракту Тома 0, п. 0.2.
- `lib/content.ts` — контент сайта: входы по задаче, кейсы, статьи.

- Реальные фото цеха и кейсы залов `[РЕАЛ]` — блоки готовы, ждут съёмки (Том 4)
- Админка сайта (Том 7), гео-страницы по городам (Том 2, п. 2.9)

## Заметки по архитектуре

- Подкатегории реализованы как измерение фильтра/чипы в рамках страницы категории,
  а товар живёт по адресу `/catalog/{category}/{product}` — чтобы избежать
  коллизии сегментов URL и дублей (Том 2, п. 2.3: товар по одному адресу).
- Весь существенный контент — в серверном рендеринге (SSR/SSG), в том числе
  характеристики и FAQ, чтобы его читали ИИ-краулеры без JS (Том 6, п. 6.1).
